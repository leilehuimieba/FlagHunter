## 一、快速开始

### 1.1 启动FlagHunter

```bash
# 确保 .env 配置正确
pentestagent
```

启动后你会看到TUI界面，底部状态栏显示当前API Provider信息：

```
[API:🟢中转站A-Claude $5.00/50 89req]  [CTF:🟢就绪]
```

### 1.2 两个核心命令

| 命令 | 用途 | 模块 |
|------|------|------|
| `/api` | 查看和管理API Provider状态 | M1 |
| `/ctf` | 进入CTF工具包模式 | M2 |

### 1.3 5分钟上手流程

```
1. pentestagent                    # 启动
2. /api                            # 查看API状态，确认🟢健康
3. /api providers                  # 查看所有配置的Provider
4. /ctf list                       # 查看可用的CTF Playbook
5. /ctf run web "http://target.com" # 执行Web类CTF Playbook
```

### 2.3 自动故障转移（无需手动操作）

M1模块后台自动完成以下流程：

```
1. 主Provider正常          → 🟢 直接使用
2. 主Provider超时/报错     → 🟡 自动重试3次
3. 重试仍失败              → 🔴 自动标记故障，切换到备用Provider
4. 备用Provider正常        → 🟢 无缝继续使用
5. 原Provider恢复          → 🟣 后台检测，验证通过后自动重新启用
```

**你什么都不用做**，M1会自动处理。你只需要关注TUI底部的状态变化。

### 2.4 预算告警

当Token消耗超过每日预算的80%时：

```
⚠️ 预算告警：今日已消耗 $40.00 / 限额 $50.00 (80%)
建议：降低请求频率或切换到更经济的Provider
```

### 3.5 Playbook半自动模式说明

M2的Playbook是**半自动**的（不是全自动），设计理由：

1. **每个Phase执行后暂停** — 工具输出发送给LLM分析
2. **LLM给出建议** — 如"发现SQL注入点，尝试union select"
3. **你确认后继续** — 输入 `/ctf next` 进入下一阶段
4. **你可以随时干预** — 直接输入命令覆盖Playbook的建议

这种模式的优势：
- ✅ **安全** — 不会自动执行危险操作
- ✅ **可控** — 每步都有人工确认
- ✅ **学习** — 看到每步的分析过程，学习解题思路
- ✅ **灵活** — Playbook走不通时随时切换策略

## 四、实战工作流

### 4.1 CTF比赛日工作流

```
Step 0: 赛前准备
  └─ 确认 .env 中所有Provider 🟢 健康
  └─ 确认 Kali VM 已启动且SSH可连
  └─ 运行 /ctf status 确认所有工具就绪

Step 1: 题目分析 (2分钟)
  └─ 浏览CTF平台，确定题目类型 (Web/Pwn/Crypto/Reverse/Misc)
  └─ 复制题目URL/IP到剪贴板

Step 2: 启动Playbook (1分钟)
  └─ /ctf run <类型> <目标>
  └─ 例: /ctf run web "http://challenge.ctf:8080"

Step 3: 跟随Playbook解题 (15-45分钟)
  └─ 每个Phase: 工具执行 → LLM分析 → 你确认 → /ctf next
  └─ 如Playbook走不通: 直接用 /ctf pwn/decode/rev 快速工具
  └─ 如找到Flag: /ctf flag "flag{xxx}"

Step 4: 提交Flag (1分钟)
  └─ /ctf flag "flag{xxx}"
  └─ 确认得分和排名
```

### 4.2 API故障应急流程

```
情况: 比赛中突然API断了，TUI显示 🔴

1. 看TUI底部: 如果已自动切换到🟢的备用Provider → 无需操作，继续比赛

2. 如果所有Provider都 🔴:
   > /api status      # 查看具体故障原因
   > /api test zz_a   # 手动测试某个Provider
   
   如果是网络问题: 检查本机网络，等待恢复
   如果是API Key过期: 联系中转站获取新Key，更新.env重启
   如果是余额不足: 切换到另一个有余额的中转站

3. 紧急备用方案:
   如果所有中转站都挂了，启动LiteLLM Proxy的保底渠道（官方API）
   或直接换到有API Key的另一个中转站账号
```

### 4.3 日常训练工作流

```
1. 打开靶机 (如TryHackMe/HackTheBox)
2. pentestagent 启动
3. 根据题型选择Playbook
4. 跟随Playbook边打边学
5. 打完复盘: /api cost 查看Token消耗
6. 优化: 根据消耗调整Provider优先级
```

## 五、常见问题

### Q1: 启动后 `/api` 命令不存在？

检查 `.env` 中 `CPA_M1_API_HUB=true`，然后重启PentestAgent。

### Q2: 所有Provider显示 🔴？

```
1. 检查网络: ping api.zz-a.com
2. 检查API Key: /api test zz_a_claude 看具体错误
3. 检查余额: 登录中转站后台查看余额
4. 检查配置: /api config 查看当前配置
```

### Q3: `/ctf` 命令显示工具 🔴？

```
1. 检查Kali VM是否启动: ping 192.168.56.101
2. 检查SSH连接: ssh kali@192.168.56.101
3. 检查 .env 中 Kali VM 配置是否正确
4. 检查子模块开关: CPA_M2_PWN_TOOLS=true 等
```

### Q4: Windows本机pwntools报错？

正常！M2的Pwn工具在**Kali VM中执行**，Windows本机不需要安装pwntools。确保Kali VM中已安装：`pip3 install pwntools`

### Q5: Playbook执行中卡住了？

```
1. 按 Ctrl+C 暂停当前Phase
2. 直接输入命令手动操作
3. 用 /ctf phase 查看当前进度
4. 用 /ctf next 跳到下一阶段
```

### Q6: 如何添加新的中转站？

编辑 `.env`，按 `CPA_PROVIDER_N_*` 格式添加新配置，递增N。重启生效。

### Q7: Token消耗太高怎么办？

```
1. /api cost — 查看哪个Provider消耗最高
2. 切换到更便宜的Provider: /api switch deepseek_official
3. 降低预算限额: CPA_M1_DAILY_BUDGET_USD=20
4. 减少不必要的LLM调用（Playbook中少用/next）
5. 使用本地模型: CPA_PROVIDER_X_MODEL=ollama/llama3
```
