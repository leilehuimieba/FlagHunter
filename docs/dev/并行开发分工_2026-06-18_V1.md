## 0. 三条铁律（违反必冲突）

1. **一个文件一个主人**：下表"可改文件"互不相交。不在你名下的文件**只读**，需要改就找集成人协调，别直接动。
2. **每会话独立 git worktree**（不是同一工作目录！）：
   ```bash
   git worktree add ../fh-<stream> -b feat/<stream> main
   ```
   各 worktree 独立工作树 + 独立分支，互不污染。完工推分支，由集成人合并。
3. **契约先定**：跨流要用到的接口（函数签名 / 返回结构）在下表"契约"列冻结；冻结后不许单方面改，要改先在本文改契约并通知。

## 3. 每流的完成定义（DoD，承治理文档）

1. 在自己 worktree 的分支上，**先写测试**（红）→ 最小实现（绿）。
2. 只跑**自己 owned 范围**的测试即可快速迭代；**不要**改 §1 热点文件让自己的测试过。
3. 完工：推分支（`git push origin feat/<stream>`），在交接里写清"改了哪些文件、新增哪些测试、契约有无变化"。
4. 集成人逐分支合并到 main，每次合并后跑**全量** `pytest tests/unit`，绿了才推。

---

## 4. 合并顺序（集成人）

知识/记忆/工具流（S1/S2/S3）与 agent/runtime/eval 流（S0）**文件不相交 → 合并零冲突**。顺序：先合独立度最高的 S1/S2/S3，再合 S0，最后协调用户 P4/P5（它动热点文件，放最后单独对齐）。
