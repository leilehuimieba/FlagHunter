# 真实解题率基线 · 方法论与 harness (V1)

Date: 2026-07-25
Status: harness 确定性骨架已落地(`flaghunter/eval/baseline/`),live 跑待操作者接基建。

## 为什么要这个

现有度量回答的是"代码没坏"(`pytest` N passed、`eval/replay` 回放确定性、
`P5 Pre-Eval` 读侧契约/脱敏/proof-boundary)。**没有一个度量回答产品北极星:
"它到底能不能稳定翻更多题、更快、更省。"** 真实靶场验证长期是散点(EasySQL /
WarmUp LFI / easy_tornado 三份 live WP),不可聚合、不可对比、不可回归。

本基线把"解题率"从轶事变成**可量化、可回归、分层预期**的数字。它与 replay
harness 正交:replay 证"读侧契约不变",baseline 证"产品结果在变好"。

## 分层题库(corpus)

`flaghunter/eval/baseline/corpus.json` 只存**稳定元数据**,不存 live URL(实例是
一次性的,每次启新 URL)。跑时用 `--targets id=url` 注入;无 target 的题记为
**SKIPPED**,绝不静默当通过。

| 层 | 含义 | 预期 verdict | 度量什么 |
|----|------|-------------|----------|
| T0 | 冒烟锚(已知能解) | solved | **回归**:锚题掉了=真退化 |
| T1 | 编目内(曲库有链) | solved | **基本盘** solve@1 |
| T2 | 编目边缘(要组合/轻推理) | near | directness / fixation 暴露区 |
| T3 | 编目外(新链/非 web) | fail | **诚实天花板**:结构上够不着有多硬 |

一个符合预期的 T3 FAIL 是**被确认的预测**,不是 bug——报告按分层预期算分,
不会把它误报成回归。

## 判定(judge)

`judge.py` 刻意与 dispatcher 内部解耦:只读运行的**外部面**(捕获的 stdout、
`--report` markdown),用纯正则导出 verdict + 成本。承载信号是 flag 匹配;steps/
tokens/tools 是 best-effort,解析不出就留空,**stdout 格式变化永不 crash 整轮**。

- **solved**:匹配到真 flag(排除占位体 `flag{...}`/`xxx`;`known_flag` 时要精确)。
- **near**:无 flag 但有近解线索(candidate/unverified/近解)。
- **fail**:无 flag 无近解线索。
- **error**:超时或崩溃无输出。
- **skipped**:没给 target。

三病归因:`fixation` / `spinning` / `reachability` 由 stdout 线索标注,进报告统计。

## runner:进程级隔离 + 三轴成本护栏

`runner.py` 逐题以 **subprocess** 驱动 `flaghunter run`。出进程跑换来三样内联路径
给不了的:每题干净的 OS 级 memory/state 重置、每轮 env 覆盖(隔离 strategy
memory)、以及**对高频内部 API 变动免疫**(只碰稳定 CLI 面)。

30 题横扫若无护栏,单题卡死能烧几小时+大量 token。**每题三轴有界**:
`timeout_s`(墙钟)× `max_loops`(agent 迭代)× 隔离 memory。

- **cold**:每题 fresh `FLAGHUNTER_STRATEGY_MEMORY_PATH` 临时库 → 记忆-off 基线。
- **warm**:全轮共享一个库累积 → 测批内记忆增益。

## cold vs warm:回答那个悬而未决的问题

记忆笔记确证过一次"warm 复跑反而退化"(单题轶事)。基线化后,`report.py` 的
**冷/暖 delta** 把"记忆到底是加分还是减分"变成一个每轮都出的百分点数字。这是
你现在最该知道、却只有轶事的事。

## 怎么跑

```bash
# 离线 plumbing 冒烟(无网/无 LLM/无工具),每层形状都走一遍
python -m flaghunter.eval.baseline --dry-run --out loot/baseline/dry

# 真 T0 锚题,冷记忆,工具走 Kali VM SSH
python -m flaghunter.eval.baseline \
    --tiers T0 --targets-file targets.json --memory cold --ssh \
    --out loot/baseline/20260725

# 冷暖对比:同题库跑两遍,合并报告出 delta
python -m flaghunter.eval.baseline --tiers T0,T1 --targets-file targets.json --memory cold --out .../cold
python -m flaghunter.eval.baseline --tiers T0,T1 --targets-file targets.json --memory warm --out .../warm
```

`targets.json`:`{"dasctf_easysql": "http://node.ctf2.dasctf.com:PORT/"}`

输出:`scorecard.json`(机读,可 diff 历轮)+ `report.md`(人读记分卡)。

## 操作者需接的 live 基建(harness 跑不了的部分)

1. `ctf2.dasctf.com/dashboard/practice` 授权实例 URL(opencli 复用 Edge 登录选题拿)。

## 边界与非目标

- 本 harness **不改 solver 行为**,只驱动+观测+记分。
- flag 判定以平台确认为最终权威;记分卡的 solved 是"抓到匹配 flag",提交平台确认
  仍需人工(与 `数据治理与知识回填_policy_2026-06-29_V1.md` 的 proof-authority 铁律一致)。
- dry-run 产出**合成**结果(按层预期塑形),行里 stamp `dry-run`,绝不当真实。
